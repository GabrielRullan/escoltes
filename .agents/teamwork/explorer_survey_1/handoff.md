## 2. Logic Chain

1. **Route Generation & Build Pipeline**:
   - `build_wiki_pages.py` is the single source of truth for generating markdown route pages.
   - `run_phase1.py` executes `build_wiki_pages.py` and then runs `mkdocs build`.
   - Any bug in `scripts/build_wiki_pages.py` propagates directly to `docs/mallorca/rutes/*.md` and ultimately to `site/`.

2. **Form Structure & Requirements Verification**:
   - The user request requires 6 fields: Nom, Email, Branca Escolta (Castors/Fures, Llops/Daines, Pioners/Rangers, Rovers/Rutes, Caps/Monitors), Agrupament Escolta, Valoració (1-5 stars), Comentari.
   - Observation in 1.2 confirms all 6 fields already exist in `get_firebase_experiences_section_html()` in `build_wiki_pages.py`.
   - The form does not ask for passwords or login tokens.
   - Validation checks for non-empty name, email format (`includes('@')`), non-empty agrupament, and minimum comment length (>= 5 chars).

3. **Firestore Model & Authorization Flag**:
   - The write logic already sets `authorized: false` when creating documents in `experiencies`.
   - The success notification string matches the required text:
     `"✅ Comentari enviat amb èxit! Està pendent d'autorització per part de l'administrador per ser visible públicament."`

4. **Public Display Filtering vs Legacy Comments**:
   - Currently, line 304 uses:
     `db.collection("experiencies").where("ruta_slug", "==", routeSlug).where("authorized", "==", true)`
   - Under Firestore query mechanics: A query `.where("authorized", "==", true)` will **never** return documents where the `authorized` field is missing/undefined.
   - If there are legacy comments stored in Firestore without the `authorized` field, they will be hidden by this query.
   - Furthermore, client-side merging already combines Firestore results with `staticExperiences` (which are legacy entries loaded from `data/experiencies_rutes.json`).
   - Therefore, to support both Firestore legacy comments (missing `authorized`) and prevent Firestore composite indexing requirements:
     Query Firestore with `.where("ruta_slug", "==", routeSlug)` and filter in the snapshot callback:
     ```javascript
     if (data.authorized === true || data.authorized === undefined) {
         fetched.push(data);
     }
     ```
     This excludes pending comments (`authorized === false`) while retaining authorized comments and legacy comments.

5. **Impact of Syntax Error 1.4**:
   - Because lines 407–409 contain extraneous tokens, the browser JavaScript runtime fails immediately when parsing the script tag.
   - Removing lines 407–409 restores complete functionality of the form and listener.

## 3. Caveats

1. **Firestore Client-Side Security**:
   - Without a Firebase backend security rule file in the repository, Firestore read/write permissions rely on the Firebase console configuration for the project `escoltes-mallorca`. If console rules require authentication, unauthenticated client `.add()` will throw a `permission-denied` error.
2. **Offline / Fallback Behavior**:
   - In lines 402–404, the `catch (error)` handler displays:
     `"✅ Comentari gravat localment. Està pendent d'autorització per l'administrador."`
     This is misleading because the comment is NOT persisted locally if Firestore fails. It should instead show an error message: `"❌ Error en enviar el comentari: Si us plau, comprova la teva connexió."`
3. **XSS Protection**:
   - User inputs (`nom`, `comentari`) are rendered via template strings without HTML character escaping. While admin approval provides moderation, client-side escaping with `escapeHtml()` is strongly advised to prevent stored XSS attacks if malicious content is approved or previewed.
4. **Agrupaments Table Restoration**:
   - Restoring the missing rows for `agrupaments_amb_dist[:2]` in `build_individual_route_pages` is a minor layout fix that should be applied at the same time to ensure clean page layout.

## 4. Conclusion

The route page generation logic in `scripts/build_wiki_pages.py` already contains the required 6 fields, the unauthenticated submission logic, and the notification string. However, **three specific fixes** are necessary:

1. **Remove the syntax error in JavaScript (Lines 407–409)**:
   Delete the stray `submitBtn.disabled = false; } };` that breaks the script block on all route pages.
2. **Update Public Filtering for Legacy Support & Index Safety**:
   In `initFirebaseExperiences` (line 302–310), query by `.where("ruta_slug", "==", routeSlug)` and filter client-side:
   `if (data.authorized === true || data.authorized === undefined) { fetched.push(data); }`
   This cleanly hides `authorized: false` pending reviews while displaying approved comments and legacy comments.
3. **Restore the Nearest Agrupaments Table Rows (Line 557)**:
   Add back the 2-line loop before the experiences section:
   ```python
   for dist, agr in agrupaments_amb_dist[:2]:
       md += f"| **{agr['nom']}** | {agr['municipi']} | **{dist:.1f} km** | [Veure Casal](../agrupaments/{agr['slug']}.md) |\n"
   ```
4. **Improve Submission Error Handling & XSS Escaping**:
   Report errors accurately when Firestore `.add()` fails instead of claiming the comment was saved, and escape user strings before DOM insertion.
